# Руководство по разработке программ/модулей zhiros

Поскольку ядро использует архитектуру Single Address Space (SAS) и динамическую линковку через реестр функций, разработка под него имеет свою специфику.

## 1. Архитектура расширений: Как это работает?
В ZhirOS нет привычных системных вызовов через прерывания int 0x80 или syscall для каждой мелочи. Взаимодействие с ядром устроено элегантнее:
1. Динамический резолвинг: При загрузке модуля ядро передает в него специальную функцию-резолвер (_resolve_function).
2. Импорт функций: С ее помощью модуль находит нужные ему функции ядра по их строковым именам (например, _printf, _getfb, _hook_interrupt).
3. Экспорт функций: Если ваш модуль добавляет новые возможности (например, драйвер мыши), он регистрирует свои функции в глобальном линкере ядра с помощью _register_function, после чего они становятся доступны консоли и другим модулям.
4. при желании модуль может переопределять ядерные функции через _replace_function

## 2. типы расширений
Вы можете писать код в разных форматах:
1. Raw-модули (.mod) — бинарные файлы, загружаемые ядром напрямую. Идеально подходят для драйверов и системных расширений.
2. ELF-программы — полноценные исполняемые файлы в формате ELF32, которые загружаются с помощью elfлоадера в модуле clitools
3. zhir lang программы - `!!пока не готов компилятор!!`
4. в будущем будет добавлена совместимость с юникс подобными системами(unixbox)

### пример кода raw модуля
```c
#include "lib/zhirtypes.h"
#include "lib/string.h"

void (*printf)(char* fmt, ...);

INIT void init(void* _resolve_function(char* name))
{
    printf = _resolve_function("_printf");//запрашиваем функцию у линковщика

    printf("hello world from module!");
}
```
### пример кода elf программы
```c
void (*printf)(char* fmt, ...);

void _start(void* (*_resolve_function)(char* name))
{
    printf = _resolve_function("_printf");//запрашиваем функцию у линковщика

    printf("hello world!\n");
}
```
